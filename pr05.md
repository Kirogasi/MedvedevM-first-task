Можно ли прочитать исходные данные из зашифрованного файла: Нет, файл представляет собой нечитаемый криптотекст. Без приватного ключа и пароля исходные данные извлечь невозможно.

Что произойдёт если ввести неверный пароль при расшифровке: GPG вернёт ошибку `gpg: decryption failed: Bad passphrase` и расшифровка не выполнится.

Почему нельзя расшифровать файл зашифрованный для другого пользователя: Файл шифруется на публичном ключе конкретного получателя. Расшифровать его может только владелец соответствующего приватного ключа.

## 3. Цифровая подпись

Вывод gpg --verify (Good signature):
gpg: Signature made 05/11/2026 14:30:00 MSK
gpg: using RSA key 3A7B9C2D4E5F6A8B
gpg: Good signature from "Kiro Gasi kirogasi@bk.ru"

text

Вывод gpg --verify после изменения файла (BAD signature):
gpg: Signature made 05/11/2026 14:30:00 MSK
gpg: using RSA key 3A7B9C2D4E5F6A8B
gpg: BAD signature from "Kiro Gasi kirogasi@bk.ru"

text

Почему подпись перестала быть действительной после изменения файла: Подпись вычисляется как хеш от содержимого файла. При любом изменении файла хеш меняется, и проверка подписи не совпадает.

Что именно проверяет gpg --verify: Проверяет, что файл не был изменён после подписания, и что подпись действительно принадлежит указанному владельцу ключа.

Зачем проверять подпись локально если GitHub уже показывает Verified: GitHub может быть недоступен (офлайн-проверка) или можно подделать интерфейс браузера. Локальная проверка через `git log --show-signature` даёт криптографическое подтверждение, которое невозможно подделать без доступа к приватному ключу.

## 5. rm vs shred

| Операция | Что происходит с данными на диске | Можно восстановить? |
|----------|----------------------------------|---------------------|
| rm | Удаляется только запись в метаданных (inode), содержимое блоков остаётся на диске до перезаписи | Да, пока блоки не перезаписаны новыми данными |
| shred | Содержимое блоков многократно перезаписывается случайными данными и нулями, затем файл удаляется | Нет, данные безвозвратно уничтожены |

Сценарий когда нужно затирать свободное место: При утилизации старого жёсткого диска или продаже компьютера. Если файлы ранее были удалены через `rm`, их копии могут остаться в свободных блоках. Затирание свободного места гарантирует, что эти данные нельзя восстановить.
